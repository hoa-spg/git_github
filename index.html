Das Praxisprojekt: dein Steckbrief-Repository

Ab Lektion 1.2 arbeitest du an einem eigenen GitHub-Repository steckbrief: eine kleine HTML-Seite über dich (wie im HTML-&-CSS-Kurs). Lektion für Lektion kommen neue Git-Techniken dazu — bis die Seite am Ende nach jedem Push automatisch geprüft und auf GitHub Pages veröffentlicht wird.

LektionProjektschritt
1.1Ordner und erste Datei vorbereiten (noch ohne Git)
1.2Repository auf GitHub anlegen, klonen, ersten Commit pushen
1.3.gitignore, mehrere saubere Commits, Historie ansehen
1.4Änderung in VS Code oder IntelliJ committen und pushen
2.1Hobby-Abschnitt auf eigenem Branch entwickeln und mergen
2.2Feature-Branch mit Rebase aktualisieren und pushen
2.3Einen Merge-Konflikt selbst erzeugen und auflösen
2.4Pull Request mit Partner-Review, Branch-Schutz für main
2.5HTML-Prüfung und Deployment auf GitHub Pages mit GitHub Actions
ℹ
Wo liegt der Projektstand?

Anders als in den anderen Kursen gibt es hier keinen Ordner beispiele/: Der Stand deines Projekts ist die Commit-Historie in deinem eigenen GitHub-Repository — genau darum geht es in diesem Kurs.

Voraussetzungen & Werkzeuge

ℹ
Empfohlenes Vorwissen

Grundkenntnisse im Umgang mit dem Terminal (Ordner wechseln, Dateien auflisten) und etwas HTML. Für Lektion 2.5 hilft der JavaScript-Kurs (npm), ist aber nicht zwingend.

Benötigte Software

Git (ab Version 2.28), ein kostenloser GitHub-Account, Visual Studio Code und/oder IntelliJ IDEA. Alles wird in Lektion 1.2 bzw. 1.4 eingerichtet.
